Metrica Bienes Raices uses a three-step, code-based password reset flow. No links are clicked — the user receives a short numeric code by email, verifies it, and then supplies a new password. All three calls are unauthenticated and require only `Content-Type: application/json`.

## Flow Overview

<Steps>
  <Step title="Request a Reset Code">
    Call `POST /forgot-password` with the user's email address. The backend locates the account and sends a time-limited verification code to that address.
  </Step>
  <Step title="Verify the Reset Code">
    Call `POST /verify-reset-code` with the email and the code the user received. A successful response confirms the code is valid and unexpired.
  </Step>
  <Step title="Set a New Password">
    Call `POST /reset-password` with the email, the verified code, and the new password (plus a confirmation). The backend validates the code once more and updates the stored password hash.
  </Step>
</Steps>

## Step 1 — `POST /forgot-password`

**Method:** `POST`  
**Path:** `/forgot-password`  
**Authentication:** None

### Request

```typescript
export interface ForgotPasswordRequest {
  email: string;
}
```

<ParamField body="email" type="string" required>
  The email address associated with the account for which the password reset is requested.
</ParamField>

### Response

```typescript
export interface ForgotPasswordResponse {
  success: boolean;
  message: string;
  error?: string;
}
```

### cURL Example

```bash
curl -X POST https://api.metricabienesraices.com/forgot-password \
  -H "Content-Type: application/json" \
  -d '{ "email": "usuario@metrica.com" }'
```

### Success Response

```json
{
  "success": true,
  "message": "Se ha enviado un código de verificación a tu correo electrónico."
}
```

### Error Response

```json
{
  "success": false,
  "message": "No existe una cuenta con ese correo electrónico.",
  "error": "NOT_FOUND"
}
```

## Step 3 — `POST /reset-password`

**Method:** `POST`  
**Path:** `/reset-password`  
**Authentication:** None

### Request

```typescript
export interface ResetPasswordRequest {
  email: string;
  code: string;
  password: string;
  password_confirmation: string;
}
```

<ParamField body="email" type="string" required>
  The account's email address, carried forward from Steps 1 and 2.
</ParamField>

<ParamField body="code" type="string" required>
  The same verification code used in Step 2. The backend re-validates it before applying the password change.
</ParamField>

<ParamField body="password" type="string" required>
  The new password. Server-side complexity rules apply.
</ParamField>

<ParamField body="password_confirmation" type="string" required>
  Must match `password` exactly. The backend rejects the request if the two values differ.
</ParamField>

### Response

```typescript
export interface ResetPasswordResponse {
  success: boolean;
  message: string;
  error?: string;
}
```

### cURL Example

```bash
curl -X POST https://api.metricabienesraices.com/reset-password \
  -H "Content-Type: application/json" \
  -d '{
    "email": "usuario@metrica.com",
    "code": "739201",
    "password": "NuevaContraseña456",
    "password_confirmation": "NuevaContraseña456"
  }'
```

### Success Response

```json
{
  "success": true,
  "message": "Contraseña actualizada correctamente."
}
```

### Error Response

```json
{
  "success": false,
  "message": "Las contraseñas no coinciden.",
  "error": "PASSWORD_MISMATCH"
}
```

## Full TypeScript Integration Example

The following mirrors the three service functions used by the password reset pages:

```typescript
import { forgotPasswordService } from "./forgot-password.service";
import { verifyCodeService } from "./verify-reset-code.service";
import { resetPasswordService } from "./reset-password.service";

async function handlePasswordReset(
  email: string,
  code: string,
  newPassword: string
): Promise<void> {
  // Step 1 — send code to email
  const forgotRes = await forgotPasswordService({ email });
  if (!forgotRes.success) throw new Error(forgotRes.message);

  // Step 2 — verify the code
  const verifyRes = await verifyCodeService({ email, code });
  if (!verifyRes.success) throw new Error(verifyRes.message);

  // Step 3 — apply new password
  const resetRes = await resetPasswordService({
    email,
    code,
    password: newPassword,
    password_confirmation: newPassword,
  });
  if (!resetRes.success) throw new Error(resetRes.message);

  console.log("Password reset complete:", resetRes.message);
}
```

<Warning>
  The verification code is time-limited. If too much time passes between Step 1 and Step 3, the backend will reject the code with an expiry error. Guide users to complete all three steps in a single session.
</Warning>

<Note>
  After a successful password reset the user is **not** automatically logged in. Redirect them to the `/iniciar-sesion` page and prompt them to sign in with their new credentials.
</Note>

## Error Handling Pattern

All three services follow the same try/catch pattern — on a non-2xx response they throw a JavaScript `Error` whose message is `result.message` from the API body (or a generic fallback if the field is absent):

```typescript
if (!response.ok) {
  throw new Error(result.message || "Ocurrió un error.");
}
```

Catch this in your form handler and surface `error.message` to the user via your alert/toast utility.

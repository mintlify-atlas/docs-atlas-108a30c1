Metrica Bienes Raices provides a self-service password recovery flow accessible from the login page via the *¿Olvidaste tu contraseña?* link, which routes to `/recuperacion-cuenta`. The flow is split across two components — `PasswordForgotPage` and `ResetPasswordUser` — and spans three API endpoints: `POST /forgot-password`, `POST /verify-reset-code`, and `POST /reset-password`. A 6-digit time-limited code is dispatched to the user's registered email address and must be verified before a new password can be set.

## Interfaces

### ForgotPasswordRequest / ForgotPasswordResponse

```typescript
// src/types/auth/forgot-password.interface.ts
export interface ForgotPasswordRequest {
  email: string;
}

export interface ForgotPasswordResponse {

  message: string;
  error?: string;
}
```

### VerifyResetCodeRequest / VerifyResetCodeResponse

```typescript

}

  success: boolean;

  error?: string;

```

### ResetPasswordRequest / ResetPasswordResponse

```typescript
// src/types/auth/reset-password.interface.ts

  email: string;

  success: boolean;
  message: string;
  error?: string;

```

## Recovery flow

<Steps>
  <Step title="User submits their email">
    On the `/recuperacion-cuenta` page the user enters the email address associated with their account and clicks **Enviar instrucciones**. The `forgotPasswordService` sends a `POST` request to trigger code generation and delivery.

    ```typescript
    // src/services/auth/forgot-password.service.ts
    export const forgotPasswordService = async (
      data: ForgotPasswordRequest
    ): Promise<ForgotPasswordResponse> => {
      const response = await fetch(`${BASE_URL}/forgot-password`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data),
      });

      const result: ForgotPasswordResponse = await response.json();
      if (!response.ok) throw new Error(result.message || 'Ocurrió un error.');
      return result;
    };
    ```

    **Request body:**
    ```json
    { "email": "usuario@ejemplo.com" }
    ```
  </Step>

  <Step title="Backend sends verification code">
    The API dispatches a 6-digit code to the provided email address. The form transitions to the code-entry view and a 15-minute countdown timer (`900` seconds) begins. The user can paste the code directly into the six individual digit inputs — the component auto-advances focus and triggers verification automatically when all six digits are filled.

    <Note>
      The **Reenviar código** button is disabled for the first 60 seconds (`timeLeft > 840`) after each send to prevent abuse. Resending resets the 15-minute timer.
    </Note>
  </Step>

  <Step title="User submits the 6-digit code">
    When the 6th digit is entered the component calls `handleVerifyCode` automatically. The `verifyCodeService` validates the email / code pair against the reset-code endpoint.

    ```typescript
    // src/services/auth/verify-reset-code.service.ts
    export const verifyCodeService = async (
      data: VerifyResetCodeRequest
    ): Promise<VerifyResetCodeResponse> => {
      const response = await fetch(`${BASE_URL}/verify-reset-code`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data),
      });

      const result: VerifyResetCodeResponse = await response.json();
      if (!response.ok) throw new Error(result.message || 'Ocurrió un error.');
      return result;
    };
    ```

    **Request body:**
    ```json
    {
      "email": "usuario@ejemplo.com",
      "code": "847321"
    }
    ```

    On success the router navigates to `/restablecer-contrasena`, passing `email` and `code` via React Router location state so that the reset form can use them without exposing them in the URL.
  </Step>

  <Step title="User sets a new password">
    The `ResetPasswordUser` component at `/restablecer-contrasena` reads `email` and `code` from router location state. The user types and confirms their new password, which is validated client-side before the API call is made.

    ```typescript
    // src/services/auth/reset-password.service.ts
    export const resetPasswordService = async (
      data: ResetPasswordRequest
    ): Promise<ResetPasswordResponse> => {
      const response = await fetch(`${BASE_URL}/reset-password`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data),
      });

      const result: ResetPasswordResponse = await response.json();
      if (!response.ok) throw new Error(result.message || 'Ocurrió un error.');
      return result;
    };
    ```

    **Request body:**
    ```json
    {
      "email": "usuario@ejemplo.com",
      "code": "847321",
      "password": "NuevaClave123",
      "password_confirmation": "NuevaClave123"
    }
    ```
  </Step>

  <Step title="Redirect to login">
    On a successful reset the user sees the API's confirmation message and is redirected to `/iniciar-sesion` with `{ replace: true }` so the reset page is removed from browser history.
  </Step>
</Steps>

## New password requirements

The `ResetPasswordUser` component enforces the same password strength rules used during registration and displays a live strength indicator:

| Rule | Required |
|---|---|
| Minimum 8 characters | ✅ Required |
| At least one uppercase letter | ✅ Required |
| At least one number | ✅ Required |
| At least one special character (`!@#$%…`) | Optional (raises strength to *Muy segura*) |

The strength bar transitions through four levels: **Débil** (red) → **Media** (yellow) → **Segura** (dark blue) → **Muy segura** (dark green).

<Warning>
  If the user navigates directly to `/restablecer-contrasena` without going through the code-verification step, `email` and `code` will be `undefined` in location state. The `validateForm()` function catches this and displays: *Enlace de restablecimiento inválido o expirado*.
</Warning>

## API summary

<CardGroup cols={2}>
  <Card title="POST /forgot-password" icon="envelope">
    Accepts `{ email }`. Triggers code generation and email delivery.
  </Card>
  <Card title="POST /verify-reset-code" icon="check">
    Accepts `{ email, code }`. Validates the 6-digit code and authorises the reset step.
  </Card>
  <Card title="POST /reset-password" icon="lock">
    Accepts `{ email, code, password, password_confirmation }`. Persists the new password.
  </Card>
  <Card title="POST /send-code" icon="paper-plane">
    Sends an email verification code via `sendVerificationCode`. Accepts `{ email, username, password }` as defined in `SendCodeData`.
  </Card>
</CardGroup>

Property management in Metrica Bienes Raices is restricted to authenticated administrators. The admin dashboard at `/administrador/propiedades` lists all properties with full status badges and action controls. From this view, admins can publish new listings via a modal, change a property's availability status, or permanently delete a record. All write operations require the `auth_token_mbr` JWT to be present in the `Authorization: Bearer` header.

## Admin property list

The `PropiedadesView` component fetches the complete admin property list on mount using the `auth_token_mbr` from the Redux store.

```http
GET ${BASE_URL}/admin-listar-propiedades
Authorization: Bearer <auth_token_mbr>
```

```typescript
// src/services/properties/get-admin-properties.service.ts
export const getPropertiesFullDataAdmin = async (
  token: string
): Promise<Property[]> => {
  const response = await fetch(`${BASE_URL}/admin-listar-propiedades`, {
    method: 'GET',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${token}`,
    },
  });

  if (!response.ok) throw new Error('Error obteniendo propiedades');

  const data = await response.json();
  return data.data || [];
};
```

The `Property` interface returned for each item in the admin list:

```typescript
// src/types/properties/admin-property.interface.ts
export interface PropertyImage {
  id: number;
  url: string;
}

export interface Property {
  id: number;
  title: string;
  price: string;

  bedrooms: number;
  bathrooms: number;
  garages: number;
  built_area: string;
  land_area: string;
  status: string;          // "Disponible" | "Vendido" | "No Disponible"
  full_address: string;
  image: PropertyImage | null;
}
```

## Creating a property

New properties are created via a publish modal triggered by the **Publicar propiedad** button. The form data is submitted as `multipart/form-data` because multiple image files are uploaded alongside the property metadata.

```http
POST ${BASE_URL}/crear-propiedad
Authorization: Bearer <auth_token_mbr>
Content-Type: multipart/form-data
```

### NewProperty type

```typescript
// src/types/properties/property.types.ts
export interface NewProperty {
  title: string;
  description: string;
  nearby_places: string[];  // array of nearby location names
  price: string;            // numeric string, e.g. "450000000"
  type_standar: string;     // e.g. "Venta" | "Arriendo"
  category: string;         // must match a propertyCategories entry
  subcategory: string;      // must match a subcategory of the chosen category
  bedrooms: number;
  bathrooms: number;
  garages: number;
  built_area: number;       // m²
  land_area: number;        // m²
  status: string;           // defaults to "Disponible"
  address: string;          // street address
  city: string;
  images?: File[];          // browser File objects from an <input type="file" multiple>
}
```

### Creating a property — step by step

<Steps>
  <Step title="Open the publish modal">
    Click **Publicar propiedad** in the admin properties header. This sets `mostrarModal` to `true` and renders the `PublishModal` component.
  </Step>

  <Step title="Fill in property details">
    Complete all required fields: title, description, price, type, category, subcategory, address, city, bedroom/bathroom/garage counts, and area measurements. Add at least one image.
  </Step>

  <Step title="Add nearby places">
    Use the `nearby_places` field to list points of interest close to the property (schools, parks, shopping centers, etc.). Each entry is a plain string. The service appends them to the `FormData` as repeated `nearby_places[]` keys:

    ```typescript
    data.nearby_places.forEach((place) => {
      formData.append('nearby_places[]', place);
    });
    ```
  </Step>

  <Step title="Attach images">
    Select images from the file picker. Each `File` object in the `images` array is appended under an indexed key so the server can process them individually:

    ```typescript
    data.images.forEach((file: File, index: number) => {
      formData.append(`images[${index}]`, file);
    });
    // Results in: images[0], images[1], images[2], …
    ```

    <Note>
      There is no hard limit enforced client-side. The backend determines the maximum number of images allowed per listing.
    </Note>
  </Step>

  <Step title="Submit to /crear-propiedad">
    The `createProperty` service builds the `FormData` object, sets the `Authorization` header (no `Content-Type` — the browser sets the multipart boundary automatically), and `POST`s to the endpoint.

    ```typescript
    // src/services/properties/post-create-property.service.ts
    const response = await fetch(`${BASE_URL}/crear-propiedad`, {
      method: 'POST',
      headers: {
        Authorization: `Bearer ${token}`,
        // Do NOT set Content-Type — browser sets multipart boundary
      },
      body: formData,
    });
    ```
  </Step>

  <Step title="List refreshed">
    On `handlePublish` the modal closes and `getPropertiesFullDataAdmin` is called again to reload the property grid with the new listing included.
  </Step>
</Steps>

## Updating property status

<Tabs>
  <Tab title="Endpoint">
    ```http
    PATCH ${BASE_URL}/update/properties/:propertyId/status
    Authorization: Bearer <auth_token_mbr>
    Content-Type: application/json
    ```

    **Request body:**
    ```json
    { "status": "Vendido" }
    ```
  </Tab>
  <Tab title="Service code">
    ```typescript
    // src/services/properties/patch-property-status.service.ts
    export type PropertyStatus = 'Disponible' | 'Vendido' | 'No Disponible';

    export async function updatePropertyStatusService(
      propertyId: number,
      status: PropertyStatus,
      token: string
    ): Promise<UpdatePropertyStatusResponse> {
      const response = await fetch(
        `${BASE_URL}/update/properties/${propertyId}/status`,
        {
          method: 'PATCH',
          headers: {
            'Content-Type': 'application/json',
            Accept: 'application/json',
            Authorization: `Bearer ${token}`,
          },
          body: JSON.stringify({ status }),
        }
      );

      const data = await response.json();
      if (!response.ok) throw new Error(data.message ?? 'Ocurrió un error.');
      return data;
    }
    ```
  </Tab>
  <Tab title="Status values">
    | Value | Badge colour | Meaning |
    |---|---|---|
    | `Disponible` | Green | Property is on the market |
    | `No Disponible` | Yellow | Temporarily off-market |
    | `Vendido` | Red | Property has been sold |
  </Tab>
</Tabs>

The `UpdatePropertyStatusModal` is triggered from the property card's yellow status-refresh button. After a successful update, `handleRefresh` reloads the property list.

## Deleting a property

```http
DELETE ${BASE_URL}/admin/delete-property/:propertyId
Authorization: Bearer <auth_token_mbr>
```

```typescript
// src/services/properties/delete-property-by-id.service.ts
export const deletePropertyByIdService = async (
  propertyId: number,
  token: string
) => {
  const response = await fetch(
    `${BASE_URL}/admin/delete-property/${propertyId}`,
    {
      method: 'DELETE',
      headers: { Authorization: `Bearer ${token}` },
    }
  );

  const text = await response.text();
  let data;
  try {
    data = JSON.parse(text);
  } catch {
    throw new Error('Respuesta inválida del servidor');
  }

  if (!response.ok) throw new Error(data?.message || 'Error eliminando propiedad');
  return data;
};
```

The `DeletePropertyById` modal is triggered from the red trash-can button on each property card. After successful deletion, `handleRefresh` reloads the grid.

<Warning>
  Property deletion is permanent. There is no soft-delete or recycle bin. Confirm with the user before calling this endpoint.
</Warning>

## FormData field reference

<ParamField body="title" type="string" required>
  Display name of the property shown on listing cards and the detail page.
</ParamField>

<ParamField body="description" type="string">
  Full property description rendered as free text on the detail page.
</ParamField>

<ParamField body="nearby_places[]" type="string[]">
  Repeated form field. Each occurrence is one nearby place name. Displayed in a modal on the public detail view.
</ParamField>

<ParamField body="price" type="string" required>
  Asking price in COP as a numeric string (e.g. `"450000000"`).
</ParamField>

<ParamField body="type_standar" type="string" required>
  Transaction type — typically `"Venta"` or `"Arriendo"`.
</ParamField>

<ParamField body="category" type="string" required>
  Top-level category from `propertyCategories` (e.g. `"Espacios Para Vivir"`).
</ParamField>

<ParamField body="subcategory" type="string" required>
  Subcategory under the chosen category (e.g. `"Apartamentos"`).
</ParamField>

<ParamField body="bedrooms" type="number" required>
  Number of bedrooms.
</ParamField>

<ParamField body="bathrooms" type="number" required>
  Number of bathrooms.
</ParamField>

<ParamField body="garages" type="number" required>
  Number of garage spaces.
</ParamField>

<ParamField body="built_area" type="number" required>
  Constructed area in square metres.
</ParamField>

<ParamField body="land_area" type="number" required>
  Total land area in square metres.
</ParamField>

<ParamField body="status" type="string">
  Initial availability status. Defaults to `"Disponible"` if omitted.
</ParamField>

<ParamField body="address" type="string" required>
  Street address of the property.
</ParamField>

<ParamField body="city" type="string" required>
  City where the property is located.
</ParamField>

<ParamField body="images[0], images[1], …" type="File">
  One `File` entry per image. The index in the bracket must be sequential starting at `0`.
</ParamField>

The **Client Dashboard** is the authenticated portal for property seekers using the Metrica Bienes Raices platform. Once a visitor creates an account and logs in, they gain access to a personalised workspace where they can browse available listings, submit interest requests directly to agents, track the progress of their cases, and manage their profile settings.

## Navigation Structure

All sidebar entries for the `Cliente` role are defined in `navigationConfig` with `roles: ['Cliente']`:

| Label | Path | Icon | Description |
|---|---|---|---|
| Dashboard | `/panel` | List | Shared summary panel (all roles) |
| Propiedades Disponibles | `/cliente/propiedad` | Building2 | Browse active property listings |
| Solicitudes | `/cliente/solicitudes` | FileText | View and manage CRM lead requests |
| Configuración | `/cliente/configuracion-perfil` | Settings | Update profile settings |

The Configuración entry has `divider: true`, rendering a visual separator above it in the sidebar.

## Available Properties View

**Route:** `/cliente/propiedad`  
**Component:** `AvailablePropertiesClient` (`available-properties.view.tsx`)

This view renders all publicly listed properties the client can browse and enquire about. Data is fetched on mount via a properties service call. Properties shown have status `Disponible`.

### Filters

The view provides three filter controls:

<ParamField query="searchTerm" type="string">
  Free-text search matched against property `title` and `location` fields (case-insensitive).
</ParamField>
<ParamField query="type" type="string">
  Dropdown populated dynamically from unique `type` values in the fetched data (e.g. Casa, Apartamento, Oficina). Selecting "Todos" clears the filter.
</ParamField>
<ParamField query="location" type="string">
  Dropdown populated dynamically from unique `location` values. Selecting "Todos" clears the filter.
</ParamField>

The filtered result set is rendered as `PropertyCardClient` components in a responsive 3-column grid. A skeleton loader (`PropertySkeleton`) is shown for each card during the fetch.

## CRM Requests View

**Route:** `/cliente/solicitudes`  
**Component:** `CRMRequestView` (`crm-requests.view.tsx`)

This view lets clients track all CRM lead requests they have submitted. Each request shows:

- A unique **ID** (e.g. `CRM-001`)
- **Client name** and **email**
- **Property type** interested in
- **Priority** badge with a trend icon
- **Status** badge
- **Assigned agent** name
- **Creation date** formatted in `es-CO` locale
- **Action buttons**: View details, Edit, Delete

The table supports client-side sort on any column and filters by status, priority, and free-text search (name, ID, or email). Clicking a row opens a detail modal.

### Status Values

| Status Key | Display Label |
|---|---|
| `pending` | Pendiente |
| `in_progress` | En Proceso |
| `completed` | Completado |
| `cancelled` | Cancelado |

### Priority Values

## Submitting a CRM Lead Request

Authenticated clients create new leads via `createLead`, which calls `POST /client-crear-lead` with a Bearer token. The `CreateLeadPayload` must be populated from property and agent selections made on the properties page:

```typescript
// src/types/leads/leads.interface.ts
export interface CreateLeadPayload {
  agent_id:    number;  // ID of the agent to assign
  property_id: number;  // ID of the property of interest
  type:        string;  // Enquiry type (e.g. "Compra", "Arriendo")
  note:        string;  // Client's message
}
```

<ParamField body="agent_id" type="number" required>
  The numeric ID of the agent the client wants to work with. Agents are listed on property detail pages.
</ParamField>
<ParamField body="property_id" type="number" required>
  The numeric ID of the property the client is enquiring about.
</ParamField>
<ParamField body="type" type="string" required>
  A category string describing the nature of the request (purchase, rental, valuation, etc.).
</ParamField>
<ParamField body="note" type="string" required>
  A free-text message from the client to the agent, included in the lead record.
</ParamField>

```typescript
// src/services/leads/create-lead.service.ts
export const createLead = async (
  payload: CreateLeadPayload,
  token:   string
): Promise<CreateLeadResponse> => {
  const response = await fetch(`${BASE_URL}/client-crear-lead`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Accept:         "application/json",
      Authorization:  `Bearer ${token}`,
    },
    body: JSON.stringify(payload),
  });
  // ...
};
```

On success the `CreateLeadResponse` (from `src/types/leads/leads.interface.ts`) returns `success`, `message`, and an optional `data` field:

```typescript
export interface CreateLeadResponse {
  success: boolean;
  message: string;
  data?:   any;
  errors?: any;
}
```

<Steps>
  <Step title="Browse available properties">
    Navigate to `/cliente/propiedad`. Use the search bar and dropdown filters to find a property of interest.
  </Step>
  <Step title="Open property details">
    Click a `PropertyCardClient` to view full property details including the assigned agent's information.
  </Step>
  <Step title="Submit a request">
    Use the lead submission form on the property detail page. Fill in `type` and `note`, then submit. The `agent_id` and `property_id` are pre-populated from the selected property.
  </Step>
  <Step title="Track your request">
    Navigate to `/cliente/solicitudes` to see the new request in the CRM table with status `Pendiente`. The assigned agent will update the status as they progress the case.
  </Step>
</Steps>

## Profile Configuration

**Route:** `/cliente/configuracion-perfil`

Clients can update their personal information (name, contact details, password) from this settings page. The route is separated from workspace features by the `divider: true` flag in `navigationConfig`.

## Data Access Scope

Clients have a read-only, self-scoped view of the platform:

- They can see **all available properties** (public endpoint, no auth required for listing).
- They can create leads **linked to themselves**, but cannot view other clients' requests.
- They **cannot** access any `/administrador/*` or `/agente/*` routes; attempting to do so is blocked by the role guard (`allowedRoles={["Cliente"]}`).

<Tip>
  The client role is the only role that does not require a Bearer token to load the properties listing. The properties catalogue can be browsed before logging in — but submitting a lead request always requires authentication.
</Tip>

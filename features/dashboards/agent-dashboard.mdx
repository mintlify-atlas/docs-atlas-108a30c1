The **Agent Dashboard** is the primary workspace for real estate agents using the Metrica Bienes Raices platform. It scopes all data to the authenticated agent—agents see only the properties, clients, and leads that have been assigned to them. The dashboard is accessible at `/panel` (shared entry point) and navigates into the `/agente/*` route namespace.

<Note>
  The Agent module is currently under active development. On load, a `ServiceAlert.info` notification is shown: *"El modulo de Agente se encuentra en desarrollo"*. The anonymous leads CRM view and the configuration page are fully functional. All KPI stat cards and chart widgets on the summary panel display static placeholder data pending live data integration.
</Note>

## Navigation Structure

All sidebar entries under the `Agente` role are defined in `navigationConfig` with `roles: ['Agente']`:

| Label | Path | Icon | Description |
|---|---|---|---|
| Dashboard | `/panel` | List | Shared summary panel (all roles) |
| Mis Propiedades | `/agente/propiedades` | Home | Properties assigned to this agent |
| Usuarios | `/agente/usuarios` | Users | Clients linked to this agent |
| Solicitudes Anónimas | `/agente/casos/anonimos` | FileText | Anonymous leads queue for this agent |
| Solicitudes (CRM) | `/agente/casos/crm` | Users | Registered client CRM leads |
| Calendario | `/agente/calendario/calendario-general` | Calendar | Agent's appointment calendar |
| Configuración | `/agente/configuracion-perfil` | Settings | Profile settings & update |

The **Casos** entry is a collapsible group containing the two case sub-routes. All other entries are direct links.

## Properties View

**Route:** `/agente/propiedades`

Renders assigned properties for this agent. Each property card exposes attribute fields (bedrooms, bathrooms, built area, land area, price) scoped to the agent's inventory. Status badges use the values `Disponible`, `No Disponible`, and `Vendido`. Agents can navigate to a property detail page for full information.

## Users / Clients View

**Route:** `/agente/usuarios`

Displays the clients that have been assigned to or are associated with this agent. Agents can view contact details and property interests but cannot create or modify user accounts directly.

## Anonymous Cases View

**Route:** `/agente/casos/anonimos`  
**Component:** `LeadAnonymousAgent` (`lead-anonymous-agent.view.tsx`)

This is the agent-scoped implementation of the anonymous leads CRM. It fetches only leads assigned to the currently authenticated agent from `GET /mostrar-leads-agente-anonimos`.

The view renders the same tab structure as the admin anonymous view (Todos / Nuevos / En Proceso / Resueltos / Visto), paginated at 15 items per page.

<Tip>
  The agent view uses `RequestCardAgentLead` (not the standard `RequestCard`). This agent-specific card component exposes the action set appropriate to agent permissions—agents can advance a lead's status but cannot transfer a case to another agent.
</Tip>

### Search & Filtering

The search bar filters by `code`. On search the view auto-switches to the tab containing the matched case code:

```typescript
if      (existeEnNuevos)    setActiveTab("nuevos");
else if (existeEnProceso)   setActiveTab("en_proceso");
else if (existeEnResueltos) setActiveTab("resueltos");
else                        setActiveTab("todos");
```

## Calendar

**Route:** `/agente/calendario/calendario-general`

The agent's personal calendar for scheduling and reviewing property visits and client meetings. This route is a direct link (not a group), reflecting that agents have a single unified calendar rather than separate general and agent-specific calendars.

## Profile Configuration

**Route:** `/agente/configuracion-perfil`

Agents can update their own profile information from this settings page. The configuration link has `divider: true` in the navigation config, so it renders with a visual separator above it in the sidebar—marking it as an account-level setting distinct from workspace features.

## Data Scoping

Every service call made from within the Agent Dashboard passes the agent's Bearer token, and the backend filters responses to only include records assigned to that agent:

| Endpoint | Scoping |
|---|---|
| `GET /mostrar-leads-agente-anonimos` | Returns only leads where `agent_id` matches the token holder |
| `GET /mostrar-solicitudes-agente` | Returns only CRM leads assigned to this agent |

<Warning>
  Agents do **not** have access to the case transfer feature or the platform-wide statistics dashboard. Attempting to navigate to `/administrador/*` routes while authenticated as an agent will be blocked by the role guard (`allowedRoles={["Agente"]}`).
</Warning>

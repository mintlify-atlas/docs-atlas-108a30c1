The **Case Transfer** feature gives Administrators the ability to re-route any anonymous case from its currently assigned agent to a different one. This is useful when an agent's workload needs to be rebalanced, when an agent is unavailable, or when a case is better suited to another agent's speciality or region.

The feature lives exclusively in the Administrator Dashboard under the **Transferencia** navigation group, accessible at the route `/administrador/transferencia/tranferir-caso`. It is restricted to users whose role is `Administrador`.

## How It Works

The transfer flow consists of two sequential API calls:

1. **Look up the case** — `POST /admin/buscar-caso-codigo` accepts a `code` string and returns the current lead details plus a list of available agents.
2. **Confirm the transfer** — `POST /caso/cambiar-agente` accepts the case `code` and the selected `user_id` (the new agent) to perform the reassignment.

Both endpoints require a valid Administrator Bearer token.

## API Reference

### Look Up Case by Code

```typescript
// src/services/leads/post-show-case-code.service.ts
export const showCaseByCodeService = async (
  code:  string,
  token: string
): Promise<ShowCaseResponse> => {
  const response = await fetch(
    `${BASE_URL}/admin/buscar-caso-codigo`,
    {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization:  `Bearer ${token}`,
      },
      body: JSON.stringify({ code }),
    }
  );
  return await response.json();
};
```

**Endpoint:** `POST /admin/buscar-caso-codigo`

<ParamField body="code" type="string" required>
  The unique case code printed on the anonymous lead record (e.g. `CASO-20240501-001`).
</ParamField>

**Response shape** (`ShowCaseResponse`):

```typescript
{
  success: boolean;
  data: {
    lead: {
      code:      string;  // Case code
      full_name: string;  // Current lead contact name (used as "Agente Actual" label)
    };
    agents_available: Array<{
      id:        number;
      full_name: string;
    }>;
  };
}
```

<ResponseField name="data.lead.code" type="string">
  The canonical code for this lead, echoed back from the backend.
</ResponseField>
<ResponseField name="data.lead.full_name" type="string">
  Display name of the current agent (or contact) assigned to the case, shown in the UI as *Agente Actual*.
</ResponseField>
<ResponseField name="data.agents_available" type="array">
  List of agents who are available to receive the case transfer. Each entry contains `id` and `full_name`.
</ResponseField>

### Transfer the Case

```typescript
// src/services/leads/post-change-agent-case.service.ts
export const changeAgentCaseService = async (
  code:    string,
  user_id: number,
  token:   string
) => {
  const response = await fetch(
    `${BASE_URL}/caso/cambiar-agente`,
    {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization:  `Bearer ${token}`,
      },
      body: JSON.stringify({ code, user_id }),
    }
  );
  return await response.json();
};
```

**Endpoint:** `POST /caso/cambiar-agente`

<ParamField body="code" type="string" required>
  The case code returned by the lookup step.
</ParamField>
<ParamField body="user_id" type="number" required>
  The `id` of the new agent selected from `agents_available`.
</ParamField>

On success the API returns `{ success: true }` and `ServiceAlert.success` is triggered with the message **"Agente Cambiado Exitosamente"**.

## Transfer Workflow

<Steps>
  <Step title="Navigate to Transfer Case">
    From the Administrator Dashboard sidebar, expand **Transferencia** and click **Transferir Caso Anonimo**. This loads the `TransferAgentCase` component at route `/administrador/transferencia/tranferir-caso`.
  </Step>
  <Step title="Enter the case code">
    Type the unique case `code` into the search input field. The code is visible on each `RequestCard` in the anonymous leads views. Press **Buscar** or click the search button to trigger `showCaseByCodeService`.
  </Step>
  <Step title="Review current assignment">
    If the lookup succeeds (`response.success === true`), the UI reveals a details panel showing the **Código del Caso** and the **Agente Actual** (current agent's name). The component sets `casoEncontrado = true`.
  </Step>
  <Step title="Select a new agent">
    A `<select>` dropdown is populated with `agents_available` returned by the API. Choose the agent you want to reassign the case to. The selected value is stored as `nuevoAgente` (agent `id` as a string).
  </Step>
  <Step title="Confirm the transfer">
    Click **Transferir Caso**. This calls `changeAgentCaseService(datosCaso.codigo, Number(nuevoAgente), token)`. On success the form resets (`casoEncontrado = false`, inputs cleared) and a success alert is displayed.
  </Step>
</Steps>

## Component State Summary

The `TransferAgentCase` view (`src/auth/dashboards/admin-dashboard/lead-transfer-agent.view.tsx`) manages the following local state:

| State variable | Type | Purpose |
|---|---|---|
| `codigo` | `string` | Raw input value for the case code search field |
| `casoEncontrado` | `boolean` | Controls visibility of the case details and agent selector |
| `datosCaso` | `{ codigo, agenteActual }` | Stores the code and current agent name from the lookup response |
| `agentes` | `Array<{ id, full_name }>` | Available agents populated from the API response |
| `nuevoAgente` | `string` | The `id` (as string) of the selected target agent |
| `loading` | `boolean` | Shows a spinner during the lookup request |
| `loadingTransfer` | `boolean` | Disables the transfer button and shows "Transfiriendo..." during the PATCH |

## Route & Access Control

| Property | Value |
|---|---|
| **Route** | `/administrador/transferencia/tranferir-caso` |
| **Navigation label** | Transferir Caso Anonimo |
| **Navigation group** | Transferencia |
| **Allowed role** | `Administrador` |
| **Navigation icon** | `MoveHorizontal` (lucide-react) |

<Warning>
  The **Transferencia** navigation group and all its children are only rendered for users with the `Administrador` role. Attempting to access the route without this role will be blocked by the application's role guard.
</Warning>

<Note>
  After a successful transfer the form resets completely. To transfer another case, the administrator must enter a new code and repeat the lookup step.
</Note>
